# 从任务到交付

## 1. 建立项目事实

- `PROJECT_BRIEF.md`：项目做什么、服务谁、真实项目在哪里。路径用你自己机器上的实际位置，模板不要填入别人的路径。
- `PROJECT_BASELINE.md`：产品、设计、工程、质量和风险原则；明确状态是“草稿”还是“已确认”。
- `CURRENT_GOAL.md`：当前阶段与下一件最重要的事。完成阶段后再更新。
- `DECISION_LOG.md`：记录已经确认且会影响未来工作的决定。暂时想法留在任务或讨论中。

## 2. 写一份可执行的任务

在 `TASKS/<任务ID>/BRIEF.md` 中写清：目标、与当前目标的关系、允许读写的范围、禁止事项、验收方法，以及是否涉及发布或外部系统。任务 ID 只用于区分工作，不代表版本号。

如果目标、权限或不可逆风险不清楚，先调查并提出具体问题。没有批准的基线时，先完成基线确认，不开始正式开发。

## 3. 执行与核验

执行者在授权范围内修改真实项目。`RESULT.md` 只记实际发生的事：改了什么、运行了哪些检查、结果如何、还有哪些风险。失败与未完成项也要写明。

对复杂或高风险工作，让没有参与实现的人查看真实变更和验证证据，再在 `REVIEW.md` 中记录结论。自评不能冒充独立审查。

## 4. 交接和人类摘要

需要换工具或换人时，用 `HANDOFF.md` 传递当前状态、证据位置、剩余工作和约束。交接不是授权扩范围。

面向人的摘要只保留结论、进度、风险和下一步。系统后台保留详细任务记录。不要把整个聊天或内部过程复制到人类前台。

## 一个最小示例

```text
目标：让本地页面在窄屏上可读。
范围：只改页面样式文件。
验收：手机宽度无横向溢出，主要操作仍可使用。
结果：记录真实改动与实测视口。
审查：按风险决定是否需要独立复查。
人类摘要：一句结论、一项风险、下一步。
```
